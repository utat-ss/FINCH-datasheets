\section{High-Level Overview}

\begin{itemize}
  \item Features an STM32G431RBT6 microcontroller
        \cite{stm32g431-datasheet}
        \begin{description}
          \item[-] 32-bit Arm Cortex-M4 processor with floating-point support
          \item[-] Maximum operating frequency of 170~MHz
          \item[-] 128~kB of internal Flash memory
          \item[-] 32~kB of SRAM
          \item[-] LQFP-64 package
        \end{description}
        
  \item Uses a 24~MHz High-Speed External (HSE) crystal and a
        32.768~kHz Low-Speed External (LSE) crystal.
        
  \item Supports communication and control through SPI,
        I\textsuperscript{2}C, UART, CAN, GPIO, timer, and analog
        connections.
\end{itemize}

\section{Introduction}

The OBC v1.2 serves as the primary processing and coordination board for the
spacecraft. It runs onboard firmware, communicates with other spacecraft
subsystems, monitors system signals, and controls board-level functions.

This datasheet documents the main electrical interfaces, functional blocks,
connectors, and implementation details of the board. It is intended to preserve
the design for future team members and support board review, manufacturing,
bring-up, and future redesign work.

\section{Functional Description}

\subsection{MCU}

The OBC uses the STM32G431RBT6 from STMicroelectronics as its main processing
device. It contains a 32-bit Arm Cortex-M4 processor with floating-point
support, 128~kB of internal Flash memory, and 32~kB of SRAM in an LQFP-64
package \cite{stm32g431-datasheet}.

The MCU runs the onboard firmware, monitors system signals, controls
board-level functions, and communicates with the other spacecraft subsystems.
The schematic assigns SPI, I\textsuperscript{2}C, UART, CAN, ADC, timer, and
GPIO connections to the MCU \cite{obc-schematic}. Detailed operation of the
connected peripherals is covered in their respective sections rather than
repeated here.

Internal meeting notes indicate that compatibility with the Zephyr
Real-Time Operating System was an important consideration during MCU
selection. The notes also show that the team preferred an STM32 device and
wanted the simplest MCU that could still meet the firmware and interface
requirements \cite{fdir-notes}. The complete MCU trade study was not located,
so the final selection reasoning should still be confirmed with the original
design lead.

\subsubsection{Power and Analog Reference}

The MCU is powered from the board's regulated 3.3~V rail. Its digital supply
pins are locally decoupled using four \(0.1\,\mu\mathrm{F}\) capacitors,
together with \(1\,\mu\mathrm{F}\) and \(4.7\,\mu\mathrm{F}\) capacitors
\cite{obc-schematic}. The smaller capacitors provide local high-frequency
decoupling, while the larger capacitors provide additional nearby charge
storage.

The analog supply, VDDA, is connected to the 3.3~V rail through a ferrite bead
and has separate local decoupling capacitors. This helps limit the amount of
digital switching noise reaching the MCU's analog circuitry
\cite{obc-schematic}.

VREF+ is supplied by a dedicated 3.0~V reference circuit based on an ATL431
programmable shunt reference. The reference is separately filtered before
reaching the MCU, providing a defined voltage reference for analog-to-digital
conversion \cite{obc-schematic}.

The VBAT pin is connected to the same regulated 3.3~V rail in this board
revision rather than to a separate backup battery supply
\cite{obc-schematic}.

\subsubsection{Reset and Fault Recovery}

The NRST pin is normally held high using a 10~k\(\Omega\) pull-up resistor. A
10~nF capacitor between NRST and ground forms an RC network that helps filter
brief disturbances on the reset line \cite{obc-schematic}. A manual reset
connection is also included for development and board testing.

The reset network can additionally be controlled by the debug interface and an
external STWD100 watchdog supervisor. If the MCU stops providing the expected
watchdog signal, the external watchdog can assert the reset line and restart
the MCU \cite{obc-schematic}.

The STM32G431 also contains independent and window watchdog peripherals
\cite{stm32g431-datasheet}. The external watchdog therefore provides an
additional recovery path that is independent of the MCU's internal firmware
execution.

\subsubsection{Programming and Debugging}

Firmware programming and hardware-level debugging are provided through the
Serial Wire Debug interface. SWDIO and SWCLK are routed from the MCU to the
OBC debug interface, allowing an external debugger to program internal Flash,
inspect memory and registers, pause execution, and step through firmware
\cite{stm32g431-datasheet,obc-schematic}.

The design also exposes SWO for optional trace output and includes a reset
connection that allows the debugger to issue a hardware reset. A separate UART
connection is routed to the Ground Support Equipment interface for
firmware-controlled communication during board bring-up, testing, and
integration \cite{obc-schematic}.

\subsubsection{External Interfaces}

The MCU communicates with the rest of the OBC through SPI,
I\textsuperscript{2}C, UART, CAN, GPIO, timer, and analog connections. These
include interfaces to the EPS, ADCS, external Flash memory, thermal-monitoring
circuitry, GNSS signals, spacecraft bus, and debug circuitry
\cite{obc-schematic}.

Only the MCU-side purpose and allocation of these interfaces are covered here.
Their detailed implementation is documented in the corresponding subsystem
sections.

\subsection{External Clocks}

The MCU is provided with both high-speed and low-speed external clock sources.

A 24~MHz crystal is connected between OSC\_IN and OSC\_OUT, with two 5.1~pF
load capacitors \cite{obc-schematic}. This provides the High-Speed External
clock source. The STM32G431 supports HSE crystals between 4~MHz and 48~MHz, so
the selected 24~MHz crystal is within the supported range
\cite{stm32g431-datasheet}.

A separate 32.768~kHz crystal is connected between OSC32\_IN and OSC32\_OUT,
with two 3.9~pF load capacitors \cite{obc-schematic}. This provides the
Low-Speed External clock source and can be used for accurate low-frequency
timing, including operation of the integrated real-time clock
\cite{stm32g431-datasheet}.

The crystal, oscillator pins, and load capacitors form an oscillator feedback
circuit. The crystal determines the frequency, while the amplifier inside the
MCU sustains the oscillation through OSC\_IN and OSC\_OUT.
STMicroelectronics recommends placing the crystal and load capacitors close to
the oscillator pins to reduce distortion and improve startup behaviour
\cite{stm32g431-datasheet}.

\subsection{External Flash Memory}

The OBC includes an SST26VF064B external serial Flash memory device. It
provides 64~Mbit, or 8~MB, of additional non-volatile storage beyond the
MCU's internal Flash memory \cite{sst26vf064b-datasheet}.

The Flash memory is connected to the MCU through SPI1 using chip select,
serial clock, MOSI, and MISO signals \cite{obc-schematic}. SPI provides a
relatively simple interface for transferring stored data without requiring a
parallel address or data bus.

The intended contents of the external Flash were not identified in the
available design notes. This section therefore does not assume whether the
memory was intended for telemetry, firmware images, logs, configuration data,
or another application.

\subsection{RTC}

Timekeeping is provided by the real-time clock peripheral integrated within
the STM32G431RBT6 rather than by a separate external RTC device
\cite{stm32g431-datasheet}.

The external 32.768~kHz crystal connected to OSC32\_IN and OSC32\_OUT can
provide the low-frequency clock used by the RTC
\cite{stm32g431-datasheet,obc-schematic}. The use of this crystal provides a
more accurate low-frequency reference than relying only on the MCU's internal
low-speed RC oscillator.

The MCU's VBAT pin supplies the RTC and backup domain when a separate backup
source is available \cite{stm32g431-datasheet}. In this board revision, VBAT
is tied to the same regulated 3.3~V rail as the rest of the MCU
\cite{obc-schematic}. The design therefore does not include an independent
battery-backed supply that would maintain the RTC after the board's 3.3~V rail
is removed.

The exact use of the RTC within the OBC firmware was not confirmed in the
available documentation.
